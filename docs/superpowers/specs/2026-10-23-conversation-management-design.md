# 客服会话管理设计

## 目标

把客服中心的历史列表升级为可长期使用的会话管理区。普通用户只能管理自己的会话，可重命名、置顶、移动到自定义分组并逻辑删除；没有任何用户问题的空会话不继续堆积。

## 已选方案

采用单一文件夹式分组：每个会话最多属于一个分组。相比多标签结构，它更适合侧栏浏览和移动操作；相比固定系统分组，它满足用户自定义整理需求。

## 数据与权限

- 新增 `conversation_groups`，包含分组 ID、所有者、名称、排序位置和时间戳。
- `conversations` 新增可空 `group_id`、`is_pinned` 和 `title_source`。`title_source` 区分自动摘要与用户命名。
- 所有会话和分组写操作必须按登录用户过滤，不能读取或修改其他用户的数据。
- 删除业务会话继续使用 `status=archived`，消息、确认、工具审计和人工工单全部保留。
- 删除分组不删除会话；组内会话移回“未分组”。

## 会话行为

- 列表先显示置顶会话，再按最后提问时间或更新时间倒序。
- 用户重命名后，首条问题摘要和后续问题不再覆盖名称。
- 取消置顶后恢复普通排序。
- 新建会话时，归档该用户此前所有 0 个问题的空会话，再创建一个新的活动会话。
- 离开一个空会话并新建另一个时，旧空会话从列表消失；当前刚创建的空会话可以保留，供用户输入第一条问题。
- 逻辑删除当前会话后，前端自动打开下一条可用会话；没有会话时显示空状态。

## 界面

- 会话行提供菜单，包含置顶/取消置顶、重命名、移动到分组、删除。
- 侧栏按分组显示，可折叠；未分组会话显示在“其他会话”。
- 提供分组管理入口，可创建、重命名和删除分组。
- 删除会话和删除分组使用明确确认，不把工具名、审计字段或内部 ID 暴露给客户。
- 桌面与移动端沿用现有历史抽屉，不增加嵌套卡片。

## API

- `PATCH /api/v1/support/conversations/{id}`：重命名、置顶或移动分组。
- `DELETE /api/v1/support/conversations/{id}`：逻辑删除。
- `GET/POST /api/v1/support/conversation-groups`：列出、创建分组。
- `PATCH/DELETE /api/v1/support/conversation-groups/{id}`：重命名或删除分组。

## 验证

- API 测试覆盖所有者隔离、重命名、置顶排序、分组生命周期、删除组回到未分组及逻辑删除。
- 服务测试覆盖新建会话时自动清理旧空会话，但不归档已有用户问题的会话。
- 静态前端测试覆盖会话菜单、分组管理、确认文案和移动端结构。
- 完整后端回归、产品栈验收和 8020 健康检查必须通过。

## 非目标

- 本阶段不提供多标签、跨用户共享分组、回收站恢复页面或物理删除。
- 不改变 Agent、MCP 工具、订单数据和写操作确认策略。
