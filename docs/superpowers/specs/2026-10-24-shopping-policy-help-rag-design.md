# 购物政策、帮助中心与 Policy RAG 设计

## 意图

为客户提供接近真实淘宝体验的购物政策与帮助中心，并让客服 Agent 在回答取消、退款、退货、换货、地址修改和争议问题时，先检索可追溯的政策证据，再结合当前订单状态作答。Policy RAG 提供解释依据，不替代订单工具、确定性 Guard 或用户确认。

## 目标

- 新增独立 `/help/`，支持政策分类、全文搜索、热门问题和条款详情。
- 以淘宝及阿里官方公开协议为主要参考，保存标题、官方 URL、适用范围、版本或抓取日期。
- 本地使用 `BAAI/bge-small-zh-v1.5` dense retrieval、中文 BM25 sparse retrieval，并以 RRF 融合排名。
- Agent 对政策类问题自动检索，回答展示政策标题和可点击来源。
- 订单相关回答同时使用检索证据与可信订单状态；政策说明不能凭空宣称当前订单可执行某项操作。
- 工程控制台可调试 query、dense/BM25 排名、RRF 分数和最终选中片段。

## 非目标

- 不抓取需要登录、验证码或绕过访问限制的淘宝页面。
- 不复制整篇淘宝协议，也不宣称本项目与淘宝存在授权或隶属关系。
- 不在首版加入外部向量数据库、HyDE、GraphRAG、多查询扩展或 reranker。
- 不让检索结果绕过 MCP、Skill、Policy Guard、fingerprint confirmation 或人工接管。
- 不把淘宝规则生硬套用到 tau2 中不存在的数据字段；缺少商品类型、签收日期或专项服务标识时必须说明无法自动判定。

## 政策口径

政策采用“淘宝官方参考规则的本项目实现版”，而不是 tau2 原始英文 policy 的中文展示。首批覆盖：

- 下单前确认商品规格、价格、数量、地址、电话与收货人。
- 待发货订单的取消或退款。
- 已发货后的退款、拒收与协商边界。
- 七天无理由退货、商品完好条件及商品页承诺优先。
- 质量问题、描述不符、错发、少发、破损等有理由售后。
- 无理由退货与质量问题下的运费责任说明。
- 换货、退款原路退回与处理时效说明。
- 地址修改与订单状态限制。
- 预售、跨境、免税、定制、生鲜和其他特殊交易例外。
- 争议协商、平台介入和其他法定处理途径。

每条本地政策包含显著说明：这是依据官方公开规则整理的本项目演示政策；具体权益取决于商品页承诺、订单事实和届时有效规则。帮助中心显示“最后核验日期”，不把抓取时间伪装成官方生效时间。

## 采用方案

### 考虑过的方案

- **仅 BGE dense**：实现最简单，但订单状态、规则名称、天数和特殊品类等精确词容易漏召回，因此不采用。
- **BGE + BM25 + RRF（采用）**：语义召回与精确词召回互补，RRF 不依赖两路原始分数标定，适合当前规模且可做清晰消融。
- **外部向量数据库加 reranker**：扩展能力更强，但会增加本地部署和运维负担；留作语料规模增长后的升级路径。

### 检索架构

采用本地双路检索：

1. 文档按标题、适用条件和语义完整段落切分，目标每片段 180 至 450 个中文字符，重叠不超过 60 字。
2. SQLite FTS5 `bm25()` 对规范化后的中文字符二元组与英文/数字词元建立倒排索引，召回 Top 20。
3. `bge-small-zh-v1.5` 生成归一化 dense embedding，余弦相似度召回 Top 20。
4. RRF 使用 `score += 1 / (60 + rank)` 融合两路名次；同一政策相邻片段去重后选择 Top 6。
5. 低于最低证据门槛时不生成确定性政策结论，转为澄清问题或建议人工处理。

选择显式 BM25 而非 BGE-M3 sparse 输出，是为了严格落实独立 dense/sparse 双路召回，同时保持模型轻量。首版不使用加权原始分数，避免两类分数尺度不可比；RRF 只融合排名。

### 存储

SQLite migration 新增：

- `policy_documents`：政策 ID、标题、分类、摘要、官方 URL、适用范围、版本、最后核验时间、启用状态。
- `policy_chunks`：chunk ID、document ID、序号、正文、token 文本、embedding、内容哈希。
- `policy_chunks_fts`：FTS5 镜像，保存预分词文本并通过 SQLite `bm25()` 执行 sparse retrieval。
- `policy_ingestion_runs`：摄取版本、模型、文档数、chunk 数、状态和错误摘要。

Embedding 以 float32 二进制保存；语料规模较小时由进程内 NumPy 计算 cosine，避免引入独立向量数据库。索引版本由文档内容哈希、chunker 版本和 embedding model 共同确定。

### 模型加载与降级

- 默认模型：`BAAI/bge-small-zh-v1.5`，只在首次索引或首次 dense 查询时懒加载。
- 模型缓存路径通过环境变量配置，默认使用 Hugging Face 本地缓存，不把权重提交仓库。
- 启动阶段不强制联网；模型未下载时帮助中心和 BM25 仍可用，API 明确返回 `dense_available=false`，不得伪装成混合检索。
- 安装脚本提供显式模型下载命令，并记录模型许可证与磁盘需求。

## 帮助中心

`/help/` 使用当前客户产品的白色、墨色、珊瑚红和绿色视觉体系：

- 顶部统一导航：客服、订单、帮助中心、消费分析、账户。
- 首屏直接提供搜索框、常见问题和政策分类，不使用营销式 Hero。
- 搜索结果显示标题、命中摘要、分类、最后核验日期和官方来源。
- 条款详情显示本项目政策正文、适用/不适用条件、相关条款、官方来源和免责声明。
- 提供“询问客服”命令，把当前政策 ID 作为受信任上下文绑定到客服会话。
- 移动端采用单列搜索与详情，不出现横向滚动。

## Agent 集成

### 检索触发

客服消息在进入 LLM planner 前通过轻量意图规则判断是否涉及政策：退款、取消、发货、物流、退货、换货、保修、运费、地址、预售、跨境、争议等。命中后调用 `PolicyRetrievalService.search(query)`；订单写操作仍按原流程使用 Retail tools。

Planner 上下文新增结构化 `POLICY_EVIDENCE`，每项只包含 chunk ID、标题、适用范围、简短正文和来源 URL。系统提示要求：

- 政策结论只能来自 evidence。
- 回答必须区分通用规则、特殊例外和当前订单事实。
- 若 evidence 冲突或缺少关键订单字段，必须说明条件并询问或转人工。
- 不得把“通常支持”写成“该订单一定支持”。

客户消息投影增加安全的 `policy_citations` block；不会向客户展示 embedding、BM25、RRF 分数或内部 prompt。

### 安全边界

- RAG 是只读知识工具，不加入写工具 allowlist。
- Guard 继续依据确定性 tool policy 和订单归属控制执行。
- 对同一订单的取消、退货或换货，Agent 必须先取得订单详情，再根据工具可执行状态提案。
- 淘宝参考规则与当前工具能力不一致时，回答明确区分“政策参考”和“当前系统可办理范围”。

## API

客户侧：

- `GET /api/v1/help/categories`
- `GET /api/v1/help/articles?category=...`
- `GET /api/v1/help/articles/{policy_id}`
- `GET /api/v1/help/search?q=...`
- `POST /api/v1/help/articles/{policy_id}/assistant`

工程侧：

- `POST /api/v1/rag/debug`：开发人员权限，返回 dense、BM25、RRF 名次和选中片段。
- `GET /api/v1/rag/status`：模型、语料版本、索引状态和最近摄取结果。

客户端不能提交自定义文档路径、模型路径或任意用户 ID。

## 可观测性与评测

- 每次 Agent 政策检索记录 `rag.started` 和 `rag.completed` 业务事件，包括 query hash、候选 ID、分数、选中片段和耗时，不保存隐藏推理链。
- 工程控制台新增 Policy RAG 调试页，支持输入 query 并比较 dense、BM25、RRF 结果。
- 建立至少 30 条中文离线查询，覆盖同义表达、订单状态、特殊商品、冲突规则和无答案问题。
- 指标包括 Recall@5、MRR@10、引用准确率、无答案拒答率、P50/P95 延迟以及 dense/BM25/RRF 消融。

## 失败处理

- BGE 未安装或权重缺失：BM25-only 并在客户回答中保持正常，工程状态明确降级。
- SQLite FTS5 不可用：返回受控服务错误，不静默伪造 BM25 分数。
- 官方来源失效：仍展示已审核摘要，来源标记“待复核”，不自动改写政策。
- 检索无证据：帮助中心显示无结果建议；Agent 询问更具体条件或建议人工服务。
- 文档冲突：优先更具体、更新且适用范围匹配的条款，并同时引用冲突条件。

## 验收

- 全部政策条目都有官方来源、适用范围和最后核验日期。
- `bge-small-zh-v1.5`、BM25 和 RRF 排名均有可复现单元测试。
- 断网且模型已缓存时能够完整检索；模型未缓存时 BM25 降级可用。
- 客户只能看到政策正文和来源，开发人员可看到检索分数。
- 订单写操作继续产生 pending confirmation，RAG 不能直接执行任何修改。
- 帮助中心桌面与移动端可用，搜索、详情和“询问客服”流程通过浏览器验收。
- 完整后端测试、Policy RAG 离线集和本地产品验收全部通过。

## 后续扩展

- 切换 BGE-M3、加入 BGE reranker 和更长政策文档。
- 定时来源复核与人工差异审批。
- 将商品页服务承诺、物流承诺和卖家专项政策作为订单级证据。
- 在真实生产数据具备后，将政策资格判断抽成版本化 deterministic eligibility service。
