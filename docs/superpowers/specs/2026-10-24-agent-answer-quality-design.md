# Agent 回答质量设计

## 目标

让客服 Agent 的最终回答像真实中文电商客服：先回答用户当前问题，只陈述工具或政策能够证明的事实，保持会话焦点，并明确下一步；不得暴露工具名、原始异常、内部状态码或推理过程。

## 方案

采用“规划与表达分层”。LLM Planner 继续负责意图、工具选择和流程推进；提示词增加统一的中文回答契约；确定性的回答合成器把工具结果转换为稳定的用户话术；质量检查器为测试和后续观测提供可解释的问题标签。没有新增第二次润色模型调用，避免增加延迟和费用。

## 回答契约

- 默认使用简体中文，保留订单号、商品名、金额等原始业务数据。
- 先直接回答当前问题，再给必要依据和一个明确下一步。
- 订单状态显示中文，必要时可附原始状态，不展示孤立的 `pending`、`delivered` 等内部值。
- 只围绕当前订单或当前目标，不因一句“取消订单”重新罗列全部订单。
- 写操作必须由 Guard 展示准确影响范围并请求确认；回答本身不能声称尚未执行的操作已经完成。
- 工具失败转换为可恢复说明，不展示 `Error:`、异常类名、工具名或后端细节。
- 政策回答区分通用规则、特殊例外和当前订单事实，并给出政策标题；没有检索证据时不伪造来源。

## 范围

本阶段覆盖 Planner 提示词、确定性工具回答、回答质量检查及自动化回归。暂不增加第二模型评审、语义记忆或生产告警。

## 验收

- 用户资料、订单详情、订单列表、商品详情和写操作结果均有中文用户化表达。
- 常见英文订单状态被稳定映射为中文。
- 原始工具错误不会直接显示给客户。
- Planner 回答契约由测试固定。
- 完整后端回归通过。
