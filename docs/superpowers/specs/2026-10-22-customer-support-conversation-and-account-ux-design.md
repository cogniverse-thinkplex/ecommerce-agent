# 客服会话、账户与反馈体验设计

## 目标

将客服中心从单页聊天演示调整为可长期使用的客户工作区。会话列表应帮助用户识别历史问题，头部只呈现有意义的账户身份，账户资料与问题反馈使用独立页面承载。

## 会话摘要

`SupportConversation` 对外返回以下口径：

- `title`：首条用户提问的确定性摘要。去除首尾空白并压缩连续空白；不超过 32 个 Unicode 字符，超出时以 `…` 结尾。尚无用户提问时为“新会话”。不调用 LLM。
- `message_count`：仅统计 `messages.role = 'user'`，表示用户提问条数。
- `last_question_at`：最后一条用户消息的 `created_at`；尚无用户提问时为空。
- `updated_at`：提交用户消息、确认或拒绝操作时更新，用于内部排序；历史列表展示优先使用 `last_question_at`。

首次用户消息与生成标题在同一事务内写入。历史记录无需批量迁移：读取摘要时若记录仍为“新会话”，从首条用户消息计算展示标题；下一次写入时持久化标题。这样既兼容旧数据，也不会伪造时间。

## 客服中心导航

左侧保留“新建会话”和会话历史。每项显示标题、用户提问数和最后提问时间；时间按浏览器本地时区格式化。客服头部移除 Retail 身份状态标签，只显示当前平台用户名称。

账户名称是进入 `/account/` 的入口；侧栏增加“问题反馈”入口，进入 `/support/feedback/`。移动端入口保留可访问名称并避免挤压标题。

## 账户资料

新增客户账户 API 与 `/account/` 页面：

- 显示当前名称、登录邮箱和购买账户已关联状态。
- 邮箱只读，因为它是平台账户与 Retail 身份的绑定键。
- 允许修改显示名称，长度 1 至 100，去除首尾空白。
- 允许通过现有“当前密码 + 新密码”流程修改密码；成功后刷新 Session 并继续停留在账户页。
- 不展示内部 `retail_user_id`，不在该页面直接修改 Retail 地址。配送地址仍由客服 Agent 的受控写操作处理。

普通客户只能修改自己的资料；开发人员账户继续使用现有管理流程。

## 问题反馈

聊天页删除“有帮助/没帮助”组件。新增独立问题反馈页面，表单包含：

- 问题类型：回答不正确、表达不清楚、响应慢、操作失败、界面问题、其他。
- 问题描述：必填，1 至 2000 字。
- 关联会话：可选，只能选择当前用户自己的会话。

现有 `feedback` 数据继续进入工程控制台“用户反馈”。为了兼容现有数据模型，新页面提交时内部使用 `rating = not_helpful`，前端不展示评分概念；新增 `interface` 分类。开发人员现有处理状态和回归用例闭环保持不变。

## API 与数据变更

- 扩展 `SupportConversation.last_question_at`。
- 消息仓储增加用户消息计数、首条用户消息、最后一条用户消息查询。
- `submit_message` 更新会话标题和更新时间。
- 新增 `PATCH /api/v1/auth/me` 修改当前客户显示名称。
- 继续使用 `POST /api/v1/auth/change-password` 修改密码。
- 反馈创建接口允许独立反馈，但关联会话时必须验证会话归属。
- SQLite 仅在需要新增反馈分类约束时增加 migration；会话标题、时间和计数均可基于现有数据计算，不重复存储计数。

## 错误与安全

- 空白名称、空白反馈、超长输入返回可恢复的 422。
- 修改其他用户资料或关联其他用户会话返回 404/403，不泄露资源是否存在。
- 账户页和反馈页沿用客服中心登录门禁；未登录跳转 `/login/`，开发人员跳转 `/dashboard/`。
- 前端网络错误继续进入已有问题采集机制，不把正常输入校验记为系统故障。

## 验收标准

1. 首次提问后列表标题变为问题摘要，刷新后保持一致。
2. 列表显示最后提问时间和用户提问条数，客服回复不增加计数。
3. 头部不再出现“订单身份已验证”，只显示可点击的用户名称。
4. 客户可修改显示名称和密码，不能修改邮箱或查看内部 Retail ID。
5. 聊天页没有评分组件；独立反馈页可以提交文字问题并可选关联本人会话。
6. 不能关联他人会话或修改他人资料。
7. 桌面和移动端均无重叠，完整后端测试和浏览器验收通过。
