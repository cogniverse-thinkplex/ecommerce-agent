# 优先级三与四：前端统一和工程观测设计

## 目标

在不重写现有产品结构的前提下，完成两项收口工作：客户侧页面使用同一套导航和状态反馈；工程控制台可以回答“系统是否健康、为什么失败、哪个版本更好”。

## 客户侧前端

- 客服中心继续作为唯一一级导航；订单、帮助、账户、消费和地址页面只保留一致的返回栏。
- 返回栏由共享脚本生成，各页面仅声明标题和返回目标，避免复制 HTML 后逐页漂移。
- 共享脚本提供加载、空数据、错误和重试状态；页面保留自己的业务布局。
- 只缓存稳定的页面外壳，不缓存身份或订单数据。所有业务数据仍以服务端结果为准。
- 移动端重点验证订单列表/详情/助手、地址表单和工程控制台。

## 工程观测

- 将 RAG、回答质量事件写入同一运行步骤链，保留政策证据和降级原因。
- 在质量总览增加 RAG 命中/降级/引用、首次响应/完整响应/工具耗时、人工处理耗时和活动告警。
- 告警来自真实运行及步骤：LLM 超时、额度问题、MCP/工具失败和 RAG 降级；不制造示例告警。
- 单次运行详情展示政策证据、工具轨迹、Token、成本和业务结果。
- 版本对比按模型、政策版本和数据版本聚合成功率、延迟、Token、成本和样本量；样本不足时明确显示。

## 数据口径

- RAG 命中：一次检索完成且至少返回一个政策片段。
- 政策引用：回答质量事件记录本轮存在可用政策证据，表示回答已获得政策上下文，不声称用户可见文本一定包含 URL。
- 首次响应：运行开始到首个回答质量事件；完整响应：运行总耗时。
- 人工处理耗时：已解决/取消工单从创建到终态的耗时。
- 版本比较只使用已有运行记录，不以演示数据填充。
