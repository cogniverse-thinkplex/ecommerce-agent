# 客户收货地址簿设计

## 目标

把当前单一默认地址表单升级为电商常见的多地址管理：客户可查看地址列表、新增、编辑、逻辑删除和设置默认地址；编辑操作进入独立页面。地址必须包含收货人、手机号、地址行、城市、州/省、国家和邮编。

## 方案与取舍

- 采用：本地 SQLite 保存完整地址簿，默认地址同步到 tau2-retail。这样可以补齐收货人、电话和多地址，同时保持 Agent 读取的默认地址一致。
- 不采用：直接扩展 tau2 数据结构。tau2 用户模型只有一个地址，升级 benchmark 数据时自定义字段容易丢失。
- 不采用：所有地址仅存本地。这样 Agent 和订单工具仍会看到旧默认地址，产生两个事实源。

## 数据模型

新增 `customer_addresses` 表：`address_id`、`owner_user_id`、`recipient_name`、`phone`、六个地址字段、`is_default`、`status`、创建/更新时间。数据库约束保证同一客户最多一个有效默认地址；删除采用 `status = archived`。

首次读取地址簿且本地无地址时，从 tau2-retail 导入当前默认地址，收货人使用零售用户姓名，电话留空并提示客户补充。缺少电话的导入地址可以展示和编辑，但不能作为新建地址的合法保存结果。

## API 与权限

- `GET /api/v1/auth/addresses`：列出当前登录客户的有效地址。
- `POST /api/v1/auth/addresses`：新增地址。
- `GET/PUT/DELETE /api/v1/auth/addresses/{address_id}`：读取、编辑、逻辑删除本人地址。
- `POST /api/v1/auth/addresses/{address_id}/default`：设为默认并同步 tau2-retail。

所有查询都同时使用 `owner_user_id` 和 `address_id`，禁止跨用户访问。API 不接受 owner 或 retail user ID。手机号不进入错误上下文与审计 payload。

## 页面流程

账户中心的“收货地址”区域展示地址卡片、默认标记、新增地址按钮，以及每项的编辑、删除、设为默认操作。点击新增或编辑进入 `/account/address/?id=...`；表单保存后返回账户中心。删除需要页面确认；默认地址不能直接删除，需先设置另一地址为默认。

## 同步与失败处理

新增第一条地址自动成为默认并同步 tau2。普通非默认地址的新增和编辑只写 SQLite；编辑默认地址或切换默认地址时同步 tau2。同步失败时事务不提交本地默认状态，页面显示可恢复错误，避免本地与 Agent 数据不一致。

## 验证

覆盖迁移、仓储所有权、默认唯一性、逻辑删除、API 越权、tau2 同步失败回滚、静态页面和移动端布局；最后运行完整测试、产品栈验收和浏览器验收。
