# 生产化第二阶段设计

## 目标

在单机生产基线之上补齐主动防护和持续运维能力：阻止登录暴力尝试，自动执行可校验备份，主动发现就绪、备份和磁盘异常，降低日志泄露风险，提供依赖安全扫描与一键验收入口。

## 设计

- 登录防护使用单进程滑动窗口，键为客户端 IP 与规范化邮箱的 SHA-256，不存储明文凭证。默认 5 次失败/5 分钟，封禁 15 分钟；成功登录清除该键。只信任 socket 客户端地址，不默认信任可伪造的转发头。
- 通用限流不干预 Agent 长任务；本阶段只保护公开登录入口，避免误伤正常客服会话。多副本部署时必须迁移到 Redis 等共享存储。
- 自动备份服务复用第一阶段 SQLite backup API，按环境变量周期运行，启动时立即备份，失败返回非零并由容器重启策略接管。
- 运维检查同时验证 `/ready`、最新备份年龄和磁盘余量，以 JSON 输出并用退出码供 cron/监控系统告警。
- 脱敏组件递归处理日志上下文中的密码、Token、Cookie、API Key、邮箱和电话；HTTP 请求日志继续坚持不记录请求体和请求头。
- 安全扫描固定为依赖漏洞审计、Python 静态安全检查和仓库秘密模式检查；工具缺失在严格模式下视为失败。
- 一键验收依次执行生产配置校验、编译、生产测试、备份恢复、秘密扫描和运行态检查，输出明确阶段结果。

## 非目标

- 不实现 WAF、验证码、短信验证、Redis 分布式限流或外部 PagerDuty/短信通知。
- 不自动删除生产数据库或旧的异地备份。
- 不把扫描器发现的问题自动升级依赖；升级仍需单独回归。

## 验收

- 登录失败达到阈值后返回 429 和 `Retry-After`，窗口到期或成功登录后恢复。
- 自动备份循环可被一次性模式测试，失败不会产生伪成功备份。
- 运维检查针对不就绪、过期备份、低磁盘分别失败并输出机器可读原因。
- 脱敏测试覆盖嵌套对象、Bearer Token、邮箱和电话。
- 安全扫描及生产验收脚本存在、无秘密并可在当前环境执行可用部分。
- 完整后端测试与真实 `/health`、`/ready` 验收通过。
